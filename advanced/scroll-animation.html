01Reveal on scroll

The bread-and-butter effect: elements start hidden and slightly offset, then fade and slide into place as they enter the viewport. The right tool is IntersectionObserver — it tells you when an element crosses a threshold without you polling scroll position on every frame.

01

Observed, not polled.

02

Transform + opacity only.

03

Unobserve after reveal.

04

Cheap and smooth.

const io = new IntersectionObserver((entries) => { for (const e of entries) { if (e.isIntersecting) { e.target.classList.add('is-visible'); io.unobserve(e.target); // reveal once, then stop watching } } }, { threshold: 0.15 }); document.querySelectorAll('.reveal').forEach(el => io.observe(el));

02Scroll progress bar

The thin gradient bar pinned to the very top of this page fills as you scroll. It is just scrollTop / (scrollHeight - clientHeight) — but the read happens inside requestAnimationFrame and the listener is passive, so it never blocks scrolling.

let ticking = false; addEventListener('scroll', () => { if (ticking) return; ticking = true; requestAnimationFrame(() => { const d = document.documentElement; const pct = d.scrollTop / (d.scrollHeight - d.clientHeight) * 100; bar.style.width = pct + '%'; ticking = false; }); }, { passive: true });
Why rAF? The scroll event can fire dozens of times per frame. Coalescing the work into a single requestAnimationFrame call (the "ticking" guard) means you only touch the DOM once per painted frame.

03Sticky / pinned scrollytelling

A graphic stays position: sticky while the text steps scroll past it. As each step becomes the active one, an IntersectionObserver swaps the pinned graphic's number, label and color. This is the pattern behind most "scrollytelling" data stories.

1
Pin the graphic

Step 1 — Pin

The graphic on the left is position: sticky; top: 80px. It sticks as long as its tall parent is in view.

Step 2 — Observe

Each text step is observed with a center-of-viewport root margin. The most centered step wins and becomes .active.

Step 3 — Swap

When the active step changes we update only the pinned graphic — cheap text and a CSS color transition, no layout recalculation.

Step 4 — Done

No manual scroll-position math, no jank: the browser does the intersection work off the main thread where it can.

const obs = new IntersectionObserver(entries => { entries.forEach(e => { if (!e.isIntersecting) return; const s = e.target; gfxNum.textContent = s.dataset.num; gfxLabel.textContent = s.dataset.label; gfx.style.background = s.dataset.color; // CSS transitions the color steps.forEach(x => x.classList.toggle('active', x === s)); }); }, { rootMargin: '-45% 0px -45% 0px' }); // "active" = crossing center

04CSS scroll-driven animation

The newest approach needs no JavaScript at all. CSS animation-timeline: scroll() links an animation to a scroll container, and view() links it to an element's progress through the viewport. It runs off the main thread, so it never janks. Below, your browser's support is detected with @supports; where it is missing we fall back to JS.

✓ Native scroll() / view() supported — the demo below is pure CSS ⚠ No native timelines — running the JavaScript fallback

This bar is linked to the whole page's scroll:

This box animates as it crosses your viewport (scroll it past):

/* Native: zero JS, runs on the compositor */ @keyframes grow { from { transform: scaleX(0); } to { transform: scaleX(1); } } @supports (animation-timeline: scroll()) { .fill { animation: grow linear; animation-timeline: scroll(root block); /* page scroll */ } .box { animation: reveal linear both; animation-timeline: view(); /* element-in-view */ animation-range: entry 10% cover 45%; } }
Browser support: Native scroll-driven animations ship in Chrome/Edge 115+ and Safari 26+. Firefox is still behind a flag at the time of writing. Always pair them with an @supports query and a JS fallback — which is exactly what powers this demo when your browser lacks them.

06The toolbox

Reach for the lightest tool that solves the job. Native APIs cover most needs now; libraries earn their bytes when you want orchestrated timelines, pinning across complex layouts, or buttery inertial scrolling.

07Performance

Scroll animation lives or dies on whether it stays at 60fps. The rules are simple and almost always the same.

  • Animate only transform and opacity. They are composited by the GPU and skip layout & paint. Animating top, left, width or margin triggers layout thrash.
  • Prefer IntersectionObserver / CSS timelines over scroll handlers. They do the work off the main thread instead of running JS every frame.
  • If you must listen to scroll, make it { passive: true } and coalesce work into one requestAnimationFrame per frame.
  • Use will-change: transform sparingly — only on elements about to animate, then remove it. Overuse wastes GPU memory.
  • Read then write. Batch DOM reads (getBoundingClientRect) separately from writes to avoid forced synchronous reflows mid-frame.
// GOOD: composited, never touches layout el.style.transform = `translateY(${y}px)`; // BAD: 'top' forces layout + paint every frame -> jank el.style.top = y + 'px';

08Honest caveats

Motion is seasoning, not the meal. The cost of getting it wrong is real and lands hardest on the users least able to opt out.

Use scroll animation responsibly:
  • Overuse hurts UX. If every element flies in, nothing feels important and reading becomes a chore. Animate to direct attention, not to decorate.
  • Motion sickness is real. Large parallax, fast scrubbing and big translate distances can trigger nausea and vestibular discomfort.
  • ALWAYS honor prefers-reduced-motion. Detect it, and ship a calm variant (instant or fade-only). The toggle in the corner of this page does exactly that.
  • Long-scroll handlers jank. Heavy work in a non-passive scroll listener blocks the main thread and stutters on low-end devices. Prefer observers / CSS timelines.
  • SEO & content-in-JS. Content hidden until a script runs may not be indexed or accessible. Keep meaning in the HTML; let animation only reveal it visually.
/* The non-negotiable baseline */ @media (prefers-reduced-motion: reduce) { * { animation: none !important; transition: none !important; } .reveal { opacity: 1; transform: none; } }
