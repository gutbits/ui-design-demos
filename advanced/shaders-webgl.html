What Is a Shader?

A shader is a small program that runs on the GPU instead of the CPU. The two you'll meet first are the vertex shader and the fragment shader.

  • Vertex shader — runs once per vertex (corner point). Its job is to decide where each point lands on screen (its gl_Position). Handles geometry, 3D transforms, perspective.
  • Fragment (pixel) shader — runs once per pixel the geometry covers. Its job is to output a color (gl_FragColor). This is where lighting, textures, gradients, plasma, and post-processing live.

They're written in GLSL (OpenGL Shading Language) — a C-like language with built-in vector types (vec2, vec3, vec4) and math (sin, mix, dot, length). The GPU runs the same shader on thousands of pixels at once — that parallelism is why it's so fast.

// GLSL basics — the vocabulary float a = 1.0; // always write floats with a decimal! vec2 uv = vec2(x, y); // 2 components — great for coords vec3 rgb = vec3(1.0, 0.0, 0.5); // a color vec4 rgba = vec4(rgb, 1.0); // rgb + alpha // swizzling: pull components in any order vec2 flipped = uv.yx; vec3 grey = color.rgb * 0.5; // built-ins do vector math for free float d = length(uv); // distance from origin vec3 c = mix(red, blue, d); // blend by amount d float w = sin(u_time + d * 10.0); // animate with the clock

The WebGL Pipeline

Geometry goes in one end, pixels come out the other. Your two shaders plug into two specific stages.

01

Buffers

Vertex data (positions, UVs) uploaded from JS to GPU memory.

02 — you

Vertex Shader

Runs per vertex. Outputs gl_Position.

03

Rasterizer

Turns triangles into the pixels they cover. Interpolates varyings.

04 — you

Fragment Shader

Runs per pixel. Outputs gl_FragColor.

05

Framebuffer

Depth test, blend, and write the final pixel to the screen.

The Shader Running Above

This is the exact plasma fragment shader powering the demo. Read it top to bottom — it's only math on a coordinate and a clock.

precision mediump float; uniform vec2 u_resolution; // canvas size in pixels uniform float u_time; // seconds since start uniform float u_scale; // zoom from the slider void main() { // normalize pixel coords to roughly -1..1, keep aspect square vec2 uv = (gl_FragCoord.xy / u_resolution) * 2.0 - 1.0; uv.x *= u_resolution.x / u_resolution.y; uv *= u_scale; float t = u_time; // classic plasma: sum of moving sine waves float v = sin(uv.x + t); v += sin(uv.y + t); v += sin(uv.x + uv.y + t); float cx = uv.x + 0.5 * sin(t / 2.0); float cy = uv.y + 0.5 * cos(t / 3.0); v += sin(sqrt(cx*cx + cy*cy) * 4.0 + t); // map the wave value into an RGB rainbow vec3 col = vec3( sin(v), sin(v + 2.094), // +120 degrees sin(v + 4.188) // +240 degrees ) * 0.5 + 0.5; gl_FragColor = vec4(col, 1.0); }
That's the whole effect. No textures, no models — just sin() on the pixel coordinate plus time. Because the GPU runs it on every pixel in parallel, it animates smoothly at 60fps even on a phone.

Shaders vs. CSS — When to Use Which

Shaders are powerful but heavier to ship and maintain. Most UI should stay in CSS. Reach for WebGL only when CSS genuinely can't do it.

NeedReach for
Hover, transitions, simple animationCSS — cheaper, accessible, no canvas, degrades gracefully.
Blur, drop-shadow, simple color filtersCSS filter / backdrop-filter.
Per-pixel generative visuals (plasma, noise, fluid)WebGL fragment shader — CSS can't compute per-pixel math.
Real-time refraction / distortion of live contentWebGL — true ray-bending (see the Liquid Glass page's honesty note).
3D scenes, particles, lighting, modelsWebGL / WebGPU (often via three.js).
Image post-processing, video effects, data viz at scaleWebGL — process thousands of points/pixels per frame.
Trade-offs of shaders: a <canvas> is opaque to the accessibility tree and to text selection/SEO, it consumes GPU/battery, and it adds JS weight. Always provide a CSS or static fallback, respect prefers-reduced-motion, and pause rendering when the canvas is off-screen.

Tools & Next Steps

  • three.js — the standard 3D library; abstracts the boilerplate while still letting you write GLSL.
  • OGL / regl — thin, low-level helpers for when you want close-to-raw WebGL.
  • Shadertoy — a huge gallery of fragment shaders you can read and remix; the plasma above is in the Shadertoy tradition.
  • The Book of Shaders (Patricio Gonzalez Vivo & Jen Lowe) — the canonical free GLSL tutorial.
  • WebGPU — the successor API (WGSL shaders, compute shaders). Shipping in modern Chrome/Edge, rolling out elsewhere.
