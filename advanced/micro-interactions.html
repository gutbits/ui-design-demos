Micro-interactions

The small moments — a button press, a toggle, a like, a loading dot — that make an interface feel alive, responsive, and human. Tiny details, outsized impact.

Advanced · Motion & Feedback

The Four Parts

Dan Saffer's model (from Microinteractions, O'Reilly 2013) breaks every micro-interaction into four parts. Get all four right and the interaction feels effortless.

01

Trigger

What starts it. A user action (click, hover, drag) or a system event (data loaded, timer fired). The trigger should be obvious and consistent.

02

Rules

What happens once triggered. The logic and constraints: what can the user do, in what order, what's allowed. Invisible, but it shapes everything.

03

Feedback

What the user sees, hears, or feels. The animation, color change, sound, or haptic that says "I heard you, here's what's happening."

04

Loops & Modes

The meta-rules: how long it lasts, what happens on repeat, and any special state. "What happens the 100th time?" "What if it's empty?"

Demo · Loading & Progress

Loaders are looping micro-interactions — they keep reassuring the user while the system works. Use a spinner for unknown waits, a progress bar for known ones.

Rule of thumb: if you know how long it'll take, show progress (a bar, a percentage). If you don't, show activity (a spinner). Under ~1s, a subtle state change often beats a spinner — flashing a loader for 200ms feels janky.

Easing — the Soul of Motion

Easing controls how a value changes over time. Linear feels robotic; eased motion feels natural because nothing in the real world starts or stops instantly. Click a card to replay.

Practical defaults: Use ease-out for elements entering or responding to a tap (fast start, gentle stop — feels snappy). Use ease-in for elements leaving the screen. Use ease-in-out for elements moving within the screen. Reserve overshoot/spring for playful, attention-worthy moments (likes, toggles) — not everything.

Duration Guidelines

Too fast and the user misses it; too slow and it's in the way. These ranges (aligned with Material Design's motion guidance) are reliable starting points.

DurationUse for
100–150msHover, small state changes, tooltips, icon toggles — near-instant feedback.
200–300msMost UI transitions: buttons, switches, expanding panels, simple fades. The everyday sweet spot.
300–400msLarger movements: modals, sheets, full-screen transitions, cards entering.
400ms+Big, deliberate, attention-drawing choreography. Rare in UI; risks feeling sluggish.
Scale duration with distance & size. A small icon flipping can be 150ms; a full-screen panel sliding in needs ~300ms+ or it feels abrupt. Larger or farther-traveling elements need a touch more time to read as natural.

Principles & Pitfalls

  • Be meaningful, not decorative. Every animation should communicate — confirm an action, show a relationship, guide attention. Motion for its own sake becomes noise.
  • Respect prefers-reduced-motion. Some users get motion sickness. Always provide a reduced-motion path that swaps big movement for simple fades.
  • Keep feedback immediate. The trigger response should begin within ~100ms or the interface feels laggy, even if the full animation runs longer.
  • Stay consistent. The same action should always feel the same. A shared set of durations and easing tokens keeps a product coherent.
  • Don't block the user. Animations should never make people wait. Let interactions be interruptible.
/* Always honor the user's motion preference */ @media (prefers-reduced-motion: reduce) { * { animation-duration: 0.01ms !important; transition-duration: 0.01ms !important; } }
