Why 3D on the Web

Used with restraint, real 3D adds something flat design cannot fake: spatial depth you can move through and inspect.

depth

Real perspective

Parallax, occlusion and lighting that respond to a moving camera read as genuinely three-dimensional, not a layered illusion.

product

360° viewers

Configurators for shoes, cars, furniture and devices let buyers orbit and customize the actual object before purchase.

immersion

Memorable scenes

Award-site hero scenes, data sculptures and interactive stories that pull people in and hold attention.

utility

Visualization

Maps, medical and scientific models, CAD previews and 3D charts where a flat projection would hide information.

The tradeoff is real: a 3D scene ships extra JavaScript, runs the GPU continuously, drains battery and is invisible to text-based tools. Treat it like a heavy ingredient — powerful in one hero moment, rarely the right choice for an entire interface.

The Stack

A short map from the raw browser API up to no-code tools. Pick the highest level that still gives you the control you need.

LayerWhat it isReach for it when
WebGLThe browser's low-level GPU graphics API (OpenGL ES based). Everything else builds on it.You want raw control or are writing your own renderer. Verbose to use directly.
WebGPUThe modern successor API — compute shaders, better performance, WGSL. Shipping in current Chrome/Edge, rolling out elsewhere.New, performance-critical work targeting modern browsers, with a WebGL fallback.
three.jsThe de-facto standard 3D library. Scenes, cameras, materials, loaders, controls over WebGL/WebGPU.Almost any custom 3D on the web. Big community, huge examples gallery.
React Three FiberA React renderer for three.js — express the scene as components and state.Your app is already React and you want declarative, reusable 3D.
Babylon.jsA full-featured engine with built-in physics, GUI, asset pipeline and a playground.Game-like or richer engine features out of the box.
SplineNo-code visual editor that designs scenes in the browser and exports an embed or React component.Designers want 3D without writing render code; quick hero scenes.
Default pick: for most projects, start with three.js (or React Three Fiber if you're in React). Drop to raw WebGL/WebGPU only for specialized performance work, and reach for Spline when a designer needs to ship a scene without code.

Building Blocks

Every three.js scene is the same five nouns. Once these click, the rest is variations on a theme.

01

Scene

The container holding every object, light and helper.

02

Camera

Your viewpoint. A PerspectiveCamera mimics human depth.

03

Renderer

Draws the scene to a <canvas> each frame via the GPU.

04

Mesh

Geometry (the shape) + material (its surface), placed in the scene.

05

Light

Without light, a StandardMaterial renders black. Ambient + point/directional.

// A minimal three.js scene — the five nouns in order const scene = new THREE.Scene(); const camera = new THREE.PerspectiveCamera(50, w/h, 0.1, 100); // fov, aspect, near, far camera.position.z = 4; const renderer = new THREE.WebGLRenderer({ antialias: true }); renderer.setSize(w, h); container.appendChild(renderer.domElement); // the <canvas> // Mesh = geometry + material const geo = new THREE.TorusKnotGeometry(1, 0.32, 160, 24); const mat = new THREE.MeshStandardMaterial({ color: 0x7aa2ff, metalness: 0.7, roughness: 0.25 }); const mesh = new THREE.Mesh(geo, mat); scene.add(mesh); // Lights — PBR materials are black without them scene.add(new THREE.AmbientLight(0xffffff, 0.4)); const key = new THREE.PointLight(0x38e1c6, 60); key.position.set(3,3,4); scene.add(key); // Render loop — runs ~60 times a second function animate() { mesh.rotation.y += 0.01; renderer.render(scene, camera); requestAnimationFrame(animate); } animate();

Performance & Accessibility — Honest Caveats

3D is the heaviest thing you can put on a page. Ship it responsibly or it quietly breaks the experience for a large share of your users.

  • Draw calls & poly budget — every separate mesh is roughly one draw call; hundreds of them stall the GPU. Merge geometry, reuse materials, and keep triangle counts modest (think tens of thousands, not millions, for web).
  • Mobile GPUs vary wildly — a scene that flies on a laptop can crawl on a budget phone. Test on real low-end hardware, cap devicePixelRatio, and consider lower-detail models for small screens.
  • Battery & heat — a continuous render loop pegs the GPU. Pause rendering when the canvas scrolls off-screen (IntersectionObserver) or the tab is hidden.
  • prefers-reduced-motion — honor it. Pause auto-rotation and continuous animation, as this demo does, for users who get motion sickness.
  • No-WebGL fallback — old devices, locked-down browsers and some accessibility tools have no WebGL. Detect it and show a static image or text, never a blank box.
  • Accessibility tree — a <canvas> is opaque to screen readers and keyboard users. Provide real text alternatives, accessible labels for controls, and don't lock essential content inside the 3D view.
  • SEO & content — search engines can't read pixels. Keep meaningful copy, headings and links in actual HTML; treat the 3D layer as enhancement, not the source of truth.
Rule of thumb: the page must be useful with the canvas removed. If turning off WebGL leaves an empty or broken page, the 3D was load-bearing in a way it shouldn't be. Enhance progressively — real content first, GPU spectacle on top.
