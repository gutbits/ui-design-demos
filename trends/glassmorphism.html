Glassmorphism

Frosted glass for the interface — translucency, blur, and light.

Glassmorphism builds UI surfaces that look like frosted glass: translucent panels that blur whatever sits behind them, defined by thin luminous borders and soft shadows, floating over a vibrant, colorful background. Everything on this page is a live demonstration — every panel is real CSS glass.

The frosted glass card

🧊

Translucency

A semi-transparent fill lets the colorful background bleed through, giving the surface depth.

🌫️

Backdrop blur

backdrop-filter: blur() frosts everything behind the panel — the defining ingredient.

✨

Luminous border

A 1px semi-white border catches the light and separates glass from glass when layers overlap.

/* The complete glassmorphism recipe */ .glass { background: rgba(255, 255, 255, 0.1); /* translucent fill */ backdrop-filter: blur(16px) saturate(160%); /* THE frosted effect */ -webkit-backdrop-filter: blur(16px) saturate(160%); /* Safari */ border: 1px solid rgba(255, 255, 255, 0.25); /* edge definition */ border-radius: 20px; box-shadow: 0 8px 32px rgba(0, 0, 0, 0.25); /* lift off the bg */ }

Note: glass only works over something interesting. A blurred panel over a flat color shows nothing — the vibrant, layered background is doing half the work.

When to use / avoid

Reach for it

  • Hero sections, dashboards, and overlays over rich imagery
  • Media-rich apps (music, photo, video) with colorful art
  • Modals, sidebars, and notification panels that float over content
  • Premium, modern, "OS-native" feeling product marketing

Be careful

  • Text-heavy or data-dense screens (blur fights legibility)
  • Low-end devices — backdrop-filter is GPU-expensive
  • Flat or plain backgrounds where the effect is invisible
  • Stacking many blurred layers at once (performance cliff)

Origin & history

The frosted-glass look has roots in Microsoft's "Aero Glass" (Windows Vista, 2007) and in Apple's iOS 7 (2013), which introduced translucent, blurred panels for Control Center and notifications. But the modern wave crystallized with macOS Big Sur (2020), whose redesigned windows, sidebars, and the menu bar leaned heavily into layered, translucent "glass" materials.

The term "Glassmorphism" was coined and popularized in 2020 by designer Michał Malewicz, who named and analyzed the trend as it spread rapidly across Dribbble, Behance, and design Twitter following Big Sur's launch. It arrived as a softer, more atmospheric counterpoint to the hard shadows of neumorphism that briefly preceded it.

What made it newly practical on the web was the maturing of the CSS backdrop-filter property, which gained broad browser support around the same period — letting designers finally blur "what's behind" an element natively, without hacks.

Defining characteristics:

  • Background blur via backdrop-filter: blur()
  • Semi-transparent fills (typically white or black at 6–20% opacity)
  • A thin, light, semi-transparent border for edge definition
  • Soft drop shadows lifting panels off the background
  • Vibrant, colorful, often gradient or photographic backgrounds
  • Multiple translucent layers to suggest depth

Accessibility & performance caveats

The #1 risk is contrast. Translucent surfaces inherit whatever is behind them, so text contrast becomes unpredictable — a label that's readable over a dark blob may vanish over a bright one. Always ensure text meets WCAG AA (4.5:1) against the worst-case background, not the best case. Adding a slight solid tint behind text or increasing fill opacity helps.
  • Performance: backdrop-filter forces real-time GPU compositing of everything behind the element. Many overlapping glass layers — especially with animated backgrounds — can drop frame rates badly on mobile and low-end hardware. Use it sparingly.
  • Browser support: requires the -webkit-backdrop-filter prefix for Safari. Provide a solid (more opaque) fallback background via @supports not (backdrop-filter: blur()) so the UI is still legible where blur isn't supported.
  • Reduced transparency: respect the user's OS-level "reduce transparency" preference where detectable, and don't make critical information depend on the blur effect.
  • Focus & hierarchy: because everything is semi-transparent and similar, take extra care that focus states and the active/primary element clearly stand out.
/* Solid fallback when backdrop-filter isn't supported */ @supports not ((backdrop-filter: blur(1px)) or (-webkit-backdrop-filter: blur(1px))) { .glass { background: rgba(40, 20, 70, 0.85); } /* opaque, still legible */ }
