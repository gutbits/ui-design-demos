Anatomy of the grid

The cleanest way to author a bento is named grid-template-areas — the CSS literally draws the layout as ASCII art, and reordering tiles is a copy-paste away.

/* The grid is an ASCII map — readable at a glance */ .bento { display: grid; gap: 16px; grid-template-columns: repeat(4, 1fr); grid-auto-rows: 130px; grid-auto-flow: dense; /* ← backfills gaps */ grid-template-areas: "hero hero stat chart" "hero hero clock chart" "icon spark spark ring " "tag toggle . ring "; } .t-hero { grid-area: hero; } .t-chart { grid-area: chart; } /* …one rule per tile — the name maps to the map above */ /* Tiles never need to know their own size or position */ .tile { border-radius: 18px; aspect-ratio: auto; container-type: inline-size; /* ← query tile width */ }

It collapses gracefully

Because the grid is just spans over columns, a single @media query drops it to one column on phones — tiles stack in source order, hero first. Resize this window past 760px and 480px to watch the real grid above re-flow.

Desktop → mobile in one rule

@media (max-width: 480px) { .bento { grid-template-columns: 1fr; } .tile { grid-column: span 1; } }

No JS, no separate mobile markup. The tiles you already wrote simply stack.

What makes a bento grid

It is not just "boxes in a grid." The good ones share a clear set of properties.

● Modular, varied-size tiles

Cards span different numbers of columns and rows. The variation is the point — it creates rhythm and signals importance.

● Visual hierarchy

The biggest tile is the headline; smaller tiles are supporting facts. Size encodes priority before a single word is read.

● One idea per tile

Each cell carries a single, self-contained thought — a stat, a feature, a visual. No tile tries to say two things.

● Scannability

Rounded corners and consistent gaps turn the page into discrete, glanceable chunks the eye can hop between.

Where it shines, where it fails

The bento is a hierarchy-and-overview format. That is also exactly where it stops working.

✓ Shines on

  • Landing pages — pitch many features at a glance, with a hero tile leading.
  • Dashboards — KPIs, charts and toggles of different weights, all visible at once.
  • Feature overviews & "what's new" pages — modular, skimmable, screenshot-friendly.
  • Marketing / keynote visuals — the Apple-style "everything in one frame" hero.

✕ Fails on

  • Content-heavy reading — articles and docs need a single measured column, not chopped tiles.
  • Linear, sequential flows — checkout, onboarding, forms — order matters more than overview.
  • Dense data tables — rows and columns of records want a table, not cards.
  • Anything that scrolls long — past one viewport the "at a glance" advantage evaporates.

How to build one

Four modern CSS tools do almost all the work — no framework required.

1. grid-template-areas

Name your regions and draw the layout as a string map. It is the most readable way to author and rearrange a bento (see the anatomy section above).

2. grid-auto-flow: dense

Let the browser backfill leftover gaps with later tiles, so mixed-size cards pack tightly without manual placement. Mind that it can reorder visual sequence.

3. aspect-ratio

Keep tiles proportional (e.g. 1 / 1 or 16 / 9) instead of pinning pixel heights, so the grid stays fluid across breakpoints.

4. Container queries

With container-type: inline-size, a tile restyles based on its own width — so the same component looks right whether it spans 1 or 4 columns.

Use it honestly

The bento is fashionable, which makes it easy to over-apply.

It can become cluttered. A wall of equally-loud tiles destroys the hierarchy that makes a bento work. If everything is emphasized, nothing is — keep one dominant tile and let the rest support it.

Reading order can break. Visual grid position is not DOM order. With grid-auto-flow: dense or area placement, the sequence a screen reader or keyboard user encounters may differ from what the eye sees. Author the DOM in a sensible reading order and use grid for layout only — never rely on visual position to convey meaning.

Don't force unrelated content into tiles. A bento implies the cells belong together. Cramming a long article, a checkout flow, or a dense table into tiles fights the format. If the content is sequential or text-heavy, reach for a normal column instead.
